# Разбор замечаний и исправления

Аудит проведён после просмотра всей недели. Исторические веса и результаты не заменены. Новые расчёты записаны отдельно в `results/methodology_audit/`. Коммитов и публикации этих исправлений пока нет; предыдущие этапы уже опубликованы.

## Исправлено

- В README разделены первоначальная оценка и адаптивные эксперименты после просмотра test. Safety DQN больше не представлена как независимый основной итог.
- Убраны два неверных утверждения об отсутствии публикации прежних этапов.
- Пороговое правило проверено на 363 допустимых парах (up 0.60–1.70, down 0.10–0.90, шаг 0.05, down < up). Оба критерия используют одну сетку: стоимость; либо лексикографически перегрузки → избыток запросов → стоимость. Выбор только по прежнему validation; тест не участвует в функции выбора. Вся процедура всё равно exploratory.
- Новые фиксированные цели достигаются из двух шардов с шагом +1 и оплатой каждого переноса. Это стратегии разгона до цели; старые fixed-результаты с бесплатным исходным размещением сохранены как исторические.
- Добавлены переоценка фиксированных траекторий при штрафах 0–160 и ценах переноса 0–16, а также повторный прогон замороженных политик при 0.5–2 исходной мощности. Это сценарии; при переоценке цен политика не переобучается.
- Сохранены решения DQN: предыдущая загрузка, число шардов, тренд и действие. График показывает наблюдаемые решения, а не универсальное правило или причинное объяснение внутренних весов.
- Добавлены посуточные диагностики нагрузки и восстановленного объёма данных, тесты общего старта, стоимости и причинности наблюдений.

## Полученные числа

На уже известном test выбранный по стоимости порог (up=1.10, down=0.85) дал 941.59 и 75 перегрузок. Выбранный по безопасности (0.95, 0.10) — 1136.39 и 3. Safety DQN — 889.65 и 2. Расширенный перебор не гарантирует хорошего обобщения: минимум стоимости на validation не означает минимум на другом дне.

Проверена и чувствительность к штрафу: при цене превышения 80 (перенос 4) исходная DQN стоит 1141.00, первоначальное пороговое правило — 977.65. Здесь сравниваются те же действия по другой цене, без переобучения; замечание подтверждено.

В validation 64 из 96 интервалов перегружены при любом из доступных чисел шардов даже с выбором по фактической нагрузке. Это нижняя граница внутри данной модели размещения, а не доказательство невозможности обслужить реальные запросы. При четырёх шардах перегружены 94 из 96 интервалов validation. Один стрессовый день — слабая основа подбора.

Восстановленный средний объём по дням: 19.81, 21.12, 21.04, 21.88, 21.06, 22.12, 21.75 МБ. Пустой старт действительно есть, но монотонный сильный рост базы к test данными не подтверждается. Нужен отдельный анализ начального прогрева, а не предположение о постоянно растущей базе.

Есть небольшая неточность в отзыве: Q-learning с 74 перегрузками хуже fixed3 (73), но лучше fixed2 (189). Это не снимает главного замечания о разных признаках.

## Не исправляется повторным обучением на той же неделе

1. Независимость оценки: старый test уже использован для изменения цели. Нужны новые периоды/кластеры после фиксации протокола; переименование старого test не восстанавливает независимость.
2. Равенство сравнения: 363 порога усиливают baseline, но число конфигураций не равно вычислительному бюджету. Требуются одинаковые признаки, цели, число оценок validation и отчёт о времени/взаимодействиях. Старый Q-learning исключён из доказательств о преимуществе алгоритма. Новая абляция ещё не выполнена.
3. Доверительные интервалы обобщения: одна неделя одного кластера недостаточна. Seed и bootstrap соседних интервалов не заменяют независимые нагрузки; такие интервалы здесь не заявляются.
4. Физическая модель: очередь, время и нагрузка миграции, операции разной стоимости, реплики, eviction и SLA всё ещё отсутствуют. Без измерений нельзя честно заменить их «реалистичными» числами. Первоначальная модель сохранена как явно ограниченная модель; производственная версия не реализована.
5. Горячие ключи: суммарные 29% у top20 сами по себе не доказывают, какие перегрузки вызваны одним ключом. В доступных агрегатах нагрузка ключей по интервалам не сохранена. Нужна отдельная проверка исходной трассы и расширение действий (например, репликация чтений с её затратами); простое добавление шардов не делит ключ.
6. Интерпретация сети: график наблюдаемых действий добавлен. Строгое объяснение причин решений и сравнение одинаковых представлений остаются отдельной задачей.

## Вывод для защиты

Проект демонстрирует реализацию JCH, причинного симулятора и нескольких управляющих политик, воспроизводимое обучение и анализ ограничений. На первой оценке DQN снизила условную стоимость ценой роста перегрузок. Последующая смена цели улучшила показатели на известном периоде; независимое обобщение пока не установлено. Это содержательный результат, даже без заявления «ИИ лучше всех».
