# Управление числом шардов кеша с обучением с подкреплением

Учебное исследование управления шардированным кешем по реальным трассам Twitter. Сравниваются фиксированная цель, пороговое правило, табличное Q-learning и DQN. Симулятор учитывает накопленную очередь, длительность миграции и стоимость обслуживания. Это не работающий кластер ClickHouse и не измерение производственного SLA.

## Данные и протокол

Используются трассы запросов к кешу, а не тексты твитов. Подготовленные данные находятся в `experiment/data/compact_cluster*`; исходные сжатые трассы скачиваются отдельно только для повторной подготовки.

| Кластер | Запросов | Ключей | Назначение |
|---|---:|---:|---|
| 7 | 9 695 769 | 44 744 | Обучение и validation |
| 10 | 1 360 998 | 680 372 | Дополнительная оценка |
| 26 | 1 649 667 | 115 325 | Дополнительная оценка |
| 45 | 2 333 422 | 639 558 | Дополнительная оценка |

Решения принимаются раз в 15 минут; допускается 2–8 шардов, все стратегии начинают с четырёх. JCH определяет размещение ключей, агент — изменение количества шардов. Ключи обрабатываются с точным UInt64-хешированием.

Весь cluster7 считается данными разработки: эту неделю уже изучали в первоначальных экспериментах. Обучение использует три суточных окна часов 24–96, validation — три следующих дня. Каждое семейство RL получает 4 настройки × 3 независимых seed × 80 эпизодов, всего 92 160 переходов. Q-learning и DQN matched получают одинаковые дискретизированные признаки; непрерывные признаки DQN рассматриваются отдельно. Пороговое правило выбирается из 60 пар, фиксированная цель — из семи вариантов; их вычислительный бюджет не равен RL.

Код, параметры и веса зафиксированы до оценки cluster10/26/45. Первые 24 часа каждого кластера используются для калибровки среды и восстановления инвентаря, следующие 144 часа (576 интервалов) — для оценки. Дополнение загрузчика для add/gets и первой секунды документировано; первоначальные отказы сохранены. Это оценка с калибровкой среды и документированным дополнением протокола.

## Основные результаты

Стоимость дана в условных модельных единицах; очередь — необработанная работа в конце интервала, не измерение latency.

| Кластер | DQN matched: стоимость / интервалы с очередью | Пороговое правило | Фиксированная цель 8 |
|---|---:|---:|---:|
| 10 | 4465,69 / 5 | 4446,70 / 63 | 4664,60 / 5 |
| 26 | 106823,40 / 546 | 106785,46 / 541 | 106823,40 / 546 |
| 45 | 6061,91 / 51 | 31916,56 / 93 | 6066,43 / 53 |

Показаны заранее выбранные политики с seed 7; остальные seed и неудачные результаты сохранены. Устойчивое превосходство ИИ не доказано. На cluster10 получен компромисс стоимости и очереди, на cluster45 фиксированная цель почти совпадает с DQN. На cluster26 несколько стратегий запускают перенос, который не завершается за время оценки.

После просмотра holdout добавлена общая проверка допустимости переноса. Она улучшает проблемный сценарий, но не считается независимым достижением нейросети. Таблицы этого отдельного эксперимента находятся в `experiment/v2_results/post_holdout_guard/`. Дальнейшая настройка потребует другого holdout.

## Структура

- `experiment/project.ipynb`, `experiment/RESULTS.md` — демонстрация и выводы.
- `experiment/v2/` — среда, обучение, протокол, оценка и основные тесты.
- `experiment/agents.py` — нейросеть; `data_pipeline.py` и `simulator.py` — зависимости сохранённого кода.
- `experiment/data/` — компактные данные для воспроизведения.
- `experiment/v2_results/` — веса кандидатов, история обучения, выбор параметров, траектории, таблицы и графики.
- `experiment/prepare_compact.py`, `compact_data.py` — подготовка и компактное исполнение.
- `experiment/guard_diagnostic.py` — отдельная проверка допустимости миграции.
- `experiment/verify_saved_traces.py` — проверка 33 траекторий и замороженных контрольных сумм.

Внутренние имена `v2` и `v2_results` сохранены, чтобы не изменять зафиксированные исходники, импорты и протоколы. Первоначальные эксперименты доступны в истории Git; в текущей структуре оставлены материалы этого исследования. Презентация хранится локально.

## Запуск демонстрации и проверок

Из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cd experiment
python -m unittest v2.test_environment v2.test_pipeline test_offset_parser test_guard test_compact test_streaming_compact
python verify_saved_traces.py
python -m jupyter lab project.ipynb
```

Ноутбук читает сохранённые результаты и не запускает обучение заново. Для проверки используются 22 теста актуального эксперимента. Окружение исходного запуска Mac/Python 3.9 записано в `requirements-lock.txt`. Для подготовки исходных трасс дополнительно нужен `zstd`. Обучение в отдельной копии описано в инструкции; не перезаписывайте замороженные результаты.

## Ограничения

Нагрузка get/set, мощность, полоса и коэффициенты затрат заданы сценарно. Очередь обслуживается пропорционально внутри шарда, без восстановления порядка отдельных запросов. Нет измеренного p99, репликации, eviction и отмены активной миграции. Изменение числа шардов не делит горячий ключ. Три кластера и зависимость от seed недостаточны для общего утверждения об оптимальности или гарантии нулевой очереди.
