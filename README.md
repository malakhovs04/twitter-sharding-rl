# Управление числом шардов кеша: учебный симулятор и RL

## Исправления модели и продолжение экспериментов

[Выполненный ноутбук 11](v2_experiment/11_finite_migration_and_holdout.ipynb) · [Полный отчёт](v2_experiment/V2_RESULTS.md) · [Воспроизведение](v2_experiment/v2/README.md)

В отдельной папке `v2_experiment/` реализованы очередь по ключам, перенос с ограниченной полосой и журналом записей, влияние копирования на обслуживание, учёт незавершённых обязательств. get/set и размеры учитываются в явно сценарных единицах работы. Это всё ещё модель кеша, не измеренный ClickHouse.

Q-learning и DQN теперь сравниваются на одинаковых дискретных признаках; DQN с непрерывными признаками — отдельная абляция. Для каждого семейства: 4 настройки × 3 независимых seed, 92 160 переходов, одинаковые три validation-окна. Веса и выбор заморожены до скачивания cluster10/26/45. Дополнение загрузчика для add/gets и первой секунды оформлено отдельно; исходные отказы сохранены.

Результат неоднозначен: DQN с дискретными признаками сокращает очередь на двух кластерах относительно порогового правила, но сильно зависит от seed; на cluster45 фиксированная цель 8 шардов почти совпадает с ней. На cluster26 ограниченная полоса приводит к незавершаемому переносу и большому накоплению очереди. Устойчивое превосходство ИИ не доказано.

Отдельная проверка допуска миграции значительно улучшила проблемный сценарий. Она создана **после просмотра holdout**, применена ко всем политикам и не засчитывается как независимый результат нейросети. Гарантии нулевых очередей нет.

Проверено: 22 новых теста, 29 прежних тестов, воспроизведение всех 33 траекторий выбранных настроек по 576 шагов, выполненный ноутбук. Компактное представление эквивалентно очередям ключей при используемой модели обслуживания; большие промежуточные массивы удалены.

## Первоначальные эксперименты и аудит

Это исследование автомасштабирования разделённого кеша с JCH по трассе Twitter. Это **не эксперимент с решардингом ClickHouse**. Связь с аналитическими БД ограничена понятиями размещения ключей, перекоса нагрузки и цены перемещений.

Данные: 9 695 769 запросов get/set, 44 744 ключа, одна неделя cluster7 sample100. Решения раз в 15 минут, 2–8 шардов. Историческое разбиение: 96/24/48 часов. Вся эта неделя уже просмотрена; новые расчёты на ней — исследовательские, а не независимый тест.

## Что действительно установлено

**Первоначальная оценка:** исходная DQN дала стоимость 779.10 и 46 перегруженных интервалов; первоначальное пороговое правило — 929.84 и 4. Экономия куплена большей перегрузкой. Превосходство нейросети по надёжности не показано. Даже этот результат ограничен неравным бюджетом настройки, одной неделей и условной моделью.

**После просмотра теста:** изменили цель и дообучили DQN; получили 889.65 и 2 перегрузки. Это исследовательский кандидат, не основной независимый результат. Последующие попытки обучения не доказали улучшение. Ноль перегрузок после подготовки резерва исключает 6 перегруженных интервалов самой подготовки.

**Аудит после замечаний:** 363 пары порогов, два заранее определённых критерия выбора на прежнем validation, одинаковый старт с двух шардов. Порог по стоимости: 941.59 / 75 перегрузок; порог по безопасности: 1136.39 / 3. Safety DQN на известном периоде: 889.65 / 2. Расширенный перебор поддерживает этот локальный результат, но не устраняет адаптацию к тесту и не уравнивает вычислительный бюджет моделей.

Полный разбор и оставшиеся ограничения: [методологический аудит](METHODOLOGY_REVIEW.md). Таблицы и график действий сети: [ноутбук 10](10_methodology_audit.ipynb). Следующий независимый эксперимент должен следовать [новому протоколу](docs/NEXT_EXPERIMENT.md).

## Границы модели

Стоимость условная: сервер 1, превышение мощности 20, перенос 4. Это не деньги. Мощность — 75-й процентиль пиков при четырёх шардах на train, а не измеренная производительность. Запросы имеют одинаковый вес; нет измеренного latency/SLA, реплик, очередей, длительности и нагрузки миграции. Поэтому гарантии отсутствия перегрузок и производственной оптимальности недопустимы.

Табличный Q-learning получает другие, грубо дискретизированные признаки. Его результат иллюстрирует конкретную реализацию; он не доказывает превосходство нейросетей над таблицами. Общие начальные веса разных seed также не дают независимых подтверждений.

## Запуск

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m jupyter lab
```

Для точного окружения исходного запуска на Mac/Python 3.9 есть requirements-lock.txt. Сжатый исходник (~49 МБ) не хранится в Git; производные агрегаты включены, поэтому тесты и оценка сохранённых моделей работают без скачивания. Для полного восстановления данных нужен zstd:

```sh
python download_data.py
python data_pipeline.py
```

Обучение исходных моделей: `python experiments.py`. Дообучение: `python safe_finetuning.py`. Эти команды запускают поиск параметров и могут перезаписать одноимённые результаты; для нового исследования используйте отдельную копию/ветку и новый период данных.
