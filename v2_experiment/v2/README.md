# Воспроизведение и границы модели

Рабочий каталог — папка `v2_experiment` (при разработке называлась `independent_v2`). Все относительные пути ниже считаются от неё. Это самостоятельная экспериментальная ветка; исходные первоначальные модели не заменены. Численное ядро MLP/Adam из прежнего `agents.py` и точный UInt64 JCH из `data_pipeline.py` переиспользованы без изменений; новый код среды, подготовки по ключам, обучения и оценки находится в `v2/`.

Зависимости: тот же Python/NumPy/pandas/matplotlib/nbformat/nbclient, что в основном проекте; для подготовки трасс установленный `zstd`. Для разработки использован Python 3.9 и окружение основного проекта.

## Проверки и чтение результатов

```sh
python -m unittest v2.test_environment v2.test_pipeline -v
python -m jupyter lab 11_finite_migration_and_holdout.ipynb
```

Ноутбук читает сохранённые CSV/JSON/PNG и не требует больших массивов данных. Полный отчёт — `V2_RESULTS.md`. Оригинальные request-level трассы и массивы NPY исключены из Git. Для локальной проверки они лежат в `data/`.

## Новый воспроизводимый запуск

Для повторения создайте отдельную копию кода с пустыми `data/` и `v2_results/`, не удаляя опубликованные результаты:

```sh
python -m v2.prepare /path/to/cluster7.sort.sample100.zst data/cluster7
python -m v2.train
python -m v2.evaluate
python build_v2_report.py
```

`train` откажется перезаписывать каталог с `frozen.json`. `evaluate` проверит хеши замороженного кода и весов, создаст отметку открытия holdout и откажется от повторного запуска. Это защита от случайной перезаписи, а не криптографическое доказательство добросовестности автора. Повторение на этих же данных воспроизводит результат, но не создаёт новый независимый тест.

## Порядок одного шага

1. На границе интервала агент видит последнюю завершённую нагрузку, накопленную очередь, остаток миграции и известный инвентарь. Запросы текущего интервала ещё недоступны.
2. Свободная от миграции среда принимает ±1 шард. Фиксируется объём снимка для ключей, меняющих владельца по JCH. Во время миграции новые команды игнорируются.
3. Записи текущего интервала в переносимые ключи добавляют свои байты в журнал. Передаётся не более заданной полосы за интервал. Раннее истечение TTL не отменяет уже учтённые обязательства.
4. Запросы обслуживаются на старом размещении. На каждом шарде все ключи получают одинаковую долю требуемого обслуживания; остаток хранится по ключам. Копирование сокращает доступную мощность.
5. Если весь снимок и журнал скопированы, размещение меняется в конце шага. Очередь не обнуляется: каждый ключ дальше обслуживается своим новым владельцем.
6. Оплачиваются серверы, реально переданные байты и накопленная очередь. На последнем шаге отдельно учитываются терминальные цены оставшейся очереди/копирования. Это аппроксимация, не утверждение о фактическом завершении.

## Почему нельзя обещать SLA

15-минутные агрегаты не позволяют восстановить p95/p99 latency и реальные очереди отдельных запросов. Fluid-сервис не FIFO; модель не содержит реплик, eviction, подтверждений записи, топологии сети и отказов. Нагрузка операции — сценарные единицы, не измеренная стоимость процессора. Действия не умеют делить горячий ключ. Вариация полосы/мощности показывает чувствительность к сценариям, но не превращает модель в промышленный ClickHouse.

Свежесть оценки означает только отсутствие использования новых кластеров при выборе моделей в этом запуске. Общий источник и малое число кластеров ограничивают обобщение. Все исключения из проверки перечислены, замены удобными трассами запрещены протоколом.

## Быстрая проверка сохранённого эксперимента

Плотные промежуточные массивы удалены после проверки: они занимали около 15 ГБ. Компактные агрегаты с сохранением исходного максимума нагрузки ключа находятся в `data/compact_cluster*`; они включены в проект. Математическая эквивалентность проверена тестами, все 33 полные траектории воспроизведены.

```sh
python -m unittest v2.test_environment v2.test_pipeline test_offset_parser test_guard test_compact test_streaming_compact
python verify_saved_traces.py
```

Для повторного построения компактных агрегатов из оригинальных файлов:

```sh
python prepare_compact.py data/cluster10.sort.sample100.zst data/compact_cluster10
```

`prepare_compact.py` включает документированное дополнение для `add`/`gets` и ненулевой первой секунды. Исторический строгий парсер оставлен неизменным для проверки хешей. Первичные отказы сохранены, дополнительная оценка записана отдельно. `resume_compact_evaluation.py` — журналированное продолжение прерванного плотного расчёта, а не новый подбор моделей.

`guard_diagnostic.py` — отдельная доработка после просмотра holdout: проверка возможности переноса. Её показатели нельзя включать в исходную независимую оценку.
